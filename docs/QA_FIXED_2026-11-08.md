## Что исправлено

- Задания: строгий диапазон прогонов, дедупликация ID и атомарное резервирование диалогов, защита от повторного платного запуска; восстановление статуса прерванных заданий и видимость всех работающих задач.
- Копии и тренировки: уникальные ID при конкуренции, откат новой записи при невозможности начать оценку.
- Чек-листы: проверка вложенных типов, конечных весов, целых неотрицательных ступеней с положительным максимумом; дробные ответы не усекаются. Пользовательские шкалы оцениваются по своим определениям, без подстановки фиксированных ступеней derive.
- Апелляции: атомарное создание и решение, защита аудита от конкурентной перезаписи; отменённое нарушение исчезает из очереди.
- История: выбранная версия учитывается до выбора последней оценки; аналитика, карта операторов и выгрузки сохраняют исторический результат. Счётчики соответствуют последней оценке.
- Расход: сохраняются usage, стоимость и трасса неуспешных ответов; учитываются повторы и подготовка кэша без двойного счёта. Трасса ошибки не выдаётся за готовую оценку.
- Ввод и аудио: некорректные типы возвращают 400, обратные временные метки отклоняются; аудио привязано к набору, кэш учитывает содержимое записи и транскрипт; статический 404 больше не рвёт соединение.
- UI: свежая проверка точного черновика перед отправкой и отдельное подтверждение стоп-сигнала; защита от устаревшего debounce-ответа; сохранение черновика чек-листа при навигации/смене роли; ссылки карточек доступны клавиатурой; адаптивные графики и шапка карточки.
- Реальный SDK: убран второй аргумент учётных данных `auth_token=""`, конфликтовавший с `api_key`. Проверка настоящего конструктора SDK подтверждает использование ключа запроса и игнорирование ключа/токена окружения.

## Бюджет и границы проверки

На границе SDK использовался временный ограничитель: заранее резервировалась верхняя оценка по входу и max_tokens, общий потолок **$0,95**. Возвращались реальные SDK-ответы; автоматические повторы SDK отключены только в этом QA-процессе. После проверки сервер остановлен, вкладка закрыта, viewport восстановлен. Рабочая БД и README не изменялись.

- Реальные вызовы проверены в режиме **одного прогона**. Многократное голосование, ошибки, конкуренция, восстановление после перезапуска и граничные данные проверены автоматическими сценариями; весь набор DEV платно не переоценивался.
- **Импорт из API организаторов реально не проверен:** `CQA_API_URL` не настроен. JSON-импорт и его ошибки проверены.
- Это проверка локальной main. Production и незавершённые изменения авторизации в отдельном deploy-worktree в этот результат не входят.
- Возврат задания в `interrupted` при запуске предполагает один владеющий процесс приложения на одну БД.
- Результат подтверждает перечисленные маршруты и исправления; он не является гарантией отсутствия любых ошибок на произвольных данных или недоступном внешнем сервисе.
