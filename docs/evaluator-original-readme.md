# CQA — оценка качества диалогов операторов

Прототип для хакатона Freedom Broker (Conversation Quality Analytics): ИИ оценивает работу оператора по чек-листу из 8 критериев, показывает баллы, объяснения и реплики-доказательства.

## Что уже есть
- `data/gold/dev_gold.json` — эталонная разметка всех 65 диалогов DEV (60 чатов + 5 звонков) по 8 критериям, со спорными местами и пояснениями.
- `config/checklist.default.json` — чек-лист как конфиг: веса, шкалы, N/A, правила толкования из памятки.
- `cqa/` — ядро: нормализация диалогов, факты кодом (эскалация, идентификация, паузы, обрыв), детерминированный расчёт баллов, промпт, JSON-схема ответа, оценщик на Claude API с голосованием и проверкой противоречий, метрики сравнения с эталоном.
- `scripts/` — загрузка набора, сводка по эталону, прогон оценщика и отчёт о точности.
- `tests/` — тесты расчёта, фактов, эталона и оценщика (с подменой API).

## Запуск
```bash
pip install -r requirements.txt
cp .env.example .env            # заполнить CQA_API_URL и ANTHROPIC_API_KEY
export $(cat .env | xargs)
python scripts/fetch_dataset.py DEV          # → data/raw/DEV.json
python scripts/gold_report.py                # сводка по эталону и итоговые баллы
python scripts/run_eval.py                   # оценка DEV + точность против эталона
python scripts/run_eval.py --votes 3         # финальный прогон с голосованием
python -m pytest -q                          # тесты
```

Контрольный набор (через 23 часа):
```bash
python scripts/fetch_dataset.py <GROUP_ID>
python scripts/run_eval.py --dataset data/raw/<GROUP_ID>.json --no-compare --votes 3
```

## Как устроена оценка
1. Диалог нормализуется: реплики получают ID `m1…mN`, время считается от начала.
2. Код считает факты: эскалация, первая реплика оператора и время реакции (порог 3 мин), подтверждение личности, события завершения, паузы > 3 мин, эвристика приветствия.
3. Claude (по умолчанию `claude-opus-5-5`, effort `high`) возвращает ответ строго по JSON-схеме: доказательства → рассуждение → ответ.
4. Ответ проверяется (ID реплик существуют, нет противоречий с фактами), при ошибке — одна повторная попытка.
5. Голосование по N прогонам: большинство для Да/Нет, медиана для шкалы; доля согласных голосов = уверенность.
6. Баллы считает код: шкала × вес, перераспределение веса при N/A, округление до 2 знаков, грубые ошибки отдельным флагом.

Стоимость одной оценки считается из `usage` ответа API и сохраняется в каждом прогоне (`data/runs/`).

## Толкование критерия 07 «Завершение»
По умолчанию (`lenient`): «Да» — прощание + итог / предложение помощи / вежливая формула («Пожалуйста. До свидания!»); «Нет» — голое прощание («Сау болыңыз!», «Bye.») или его отсутствие; N/A — клиент ушёл или связь прервалась. Альтернативы: `--policy strict` (только итог или предложение помощи) и `--policy any_farewell`. Подробности — в `docs/decision-log.md`.
