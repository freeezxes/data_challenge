# Защита CQA: сценарий на 5 минут

Главная мысль, которую жюри должно унести: **модель оценивает живьём, каждый балл можно проверить по реплике, а человек всегда может поправить**. Все функции показываем внутри четырёх блоков из гайда, без отдельного «тура по фичам».

Роли: **ведущий** говорит, **пилот** кликает. Если вы вдвоём — так быстрее и спокойнее. Пилот не говорит, ведущий не трогает мышь.

---

## Подготовка

### После выдачи контрольного набора (час 23)

1. Главная → «Загрузить по group_id» → значение от организаторов.
2. Очередь → набор «CONTROL» → режим «3 прогона» → «Оценить неоценённые». 10 диалогов — около 2 минут, около $1,5.
3. Пройдитесь по контрольным диалогам и выберите **демо-диалог**: чат, где есть и снижение, и «Не применяется». Запишите его ID и цифры (итог, какой критерий снижен, у какого N/A). Если в наборе есть звонок — запишите и его.
4. Для апелляции выберите в демо-диалоге критерий, по которому оценка спорная: у него «2 из 3» или «разброс», либо фильтр «Модель сомневается». Так второе мнение покажет что-то интересное.
5. Чтобы очередь не была пустой, дооцените DEV: либо целиком в режиме «1 прогон» (около $2,8), либо хотя бы `p1-ru-009`, `p1-ru-001`, `p4-ru-003`.

### За 30 минут до выступления

- [ ] Сервер запущен с ключом: в терминале строка «ключ API: есть».
- [ ] Один пробный «Оценить заново» прошёл. Проверка ключа и сети, около $0,12.
- [ ] Резервная копия базы после подготовки — откатиться после репетиций:
  ```
  copy data\cqa.db data\cqa.demo.db        (Windows)
  cp data/cqa.db data/cqa.demo.db          (macOS/Linux)
  ```
  Перед выходом верните её на место при остановленном сервере.
- [ ] Апелляций «Ждут решения» — 0. Иначе бейдж и список отвлекут.
- [ ] Роль — «Оператор».
- [ ] Браузер: масштаб 110–125% (на проекторе мелкий текст не читается), полноэкранный режим, уведомления выключены, лишние вкладки закрыты.
- [ ] Тёмную тему проверьте **на самом проекторе**: если тёмно-серое сливается, поднимите яркость или увеличьте масштаб.
- [ ] Интернет: оценка идёт через API, поэтому держите раздачу с телефона как запасной канал.
- [ ] **Запасное видео:** запишите экран с прогоном всего сценария. Если API или сеть упадут, показываете запись и говорите «вот так это работает вживую».

Открытые вкладки по порядку: Очередь (CONTROL) · карточка демо-диалога · Апелляции · Чек-листы.

## Сценарий

### 0:00–1:00 · Интерфейс и выбранный диалог

**Пилот:** Очередь, набор CONTROL. Пробежать по фильтрам: «Грубые нарушения», «Модель сомневается». Открыть демо-диалог и сразу нажать **«Оценить заново»**.

**Ведущий:**
> «Это CQA. Оценщик качества для чатов и звонков Freedom Broker на русском, казахском и английском. Перед вами контрольный набор, который нам выдали час назад: он уже оценён, зелёным — порядок, красным — грубые нарушения, жёлтым — где модель сомневается.
>
> Чтобы было видно, что это не заготовка, оцениваю этот диалог заново прямо сейчас».

Пока справа идёт «Прямой эфир» (около 10 секунд модель думает, потом критерии появляются по одному):
> «Модель — Claude Opus. Она получает чек-лист и диалог и пишет оценку по каждому критерию — видно, как критерии появляются, а в переписке подсвечиваются реплики, на которые она опирается. Важное: итог считает не модель, а код — по весам и правилам чек-листа».

### 1:00–3:00 · Оценка, обоснование, переход к реплике, N/A, итог

**Пилот** — по одному действию на фразу ведущего:

1. Итог вверху и баллы справа:
   > «У каждого критерия — ответ, баллы с учётом веса, объяснение и дословная цитата».
2. «Перейти к …» у сниженного критерия, транскрипт прокручивается и подсвечивает реплику:
   > «Ссылка ведёт прямо на реплику. Если действие пропущено — показываем проверенный участок».
3. Критерий «Не применяется»:
   > «Здесь N/A: условие неприменимости выполнено, объяснение рядом. Вес этого критерия перераспределён между остальными, поэтому максимум по-прежнему 100, а у остальных критериев вес больше номинального».
4. Итог внизу. Если есть грубое нарушение — плашка:
   > «Грубое нарушение на баллы не влияет, отмечается отдельно — как в чек-листе».
5. «Как получена оценка» (5 секунд, сразу закрыть):
   > «Здесь всё, что ушло в модель, её сырой ответ, токены и стоимость. Одна оценка — примерно 12 центов, три прогона с голосованием».
6. *Если есть звонок и укладываетесь по времени (20 секунд):* открыть звонок, кликнуть по волне:
   > «В звонках — запись, клик по волне или времени реплики перематывает на это место. Зелёное — оператор, серое — клиент; плюс темп речи и интонация, которые считает код».

### 3:00–4:00 · Апелляция, решение, новый итог

**Пилот:** в карточке у выбранного критерия — **«Оспорить»**, вставить заготовленный комментарий → «Отправить апелляцию».

**Ведущий:**
> «Оператор не согласен и оспаривает оценку с комментарием».

**Пилот:** роль **«Проверяющий»** (вверху справа) → вкладка «Апелляции» → **«Спросить»** второе мнение (около 10 секунд).

**Ведущий, пока ждём:**
> «Проверяющий видит спорную оценку, комментарий и фрагмент диалога. Модель может дать второе мнение — перечитать критерий с учётом довода оператора. Но решает человек».

**Пилот:** «Взять предложение» (или выбрать ступень вручную) → причина уже заполнена → «Изменить оценку». Открыть ссылку на диалог.

**Ведущий:**
> «Итог пересчитан. В карточке видно и исходную оценку, и решение с причиной, и финальный балл — оценка модели не переписывается».

### 4:00–5:00 · Замена критерия и применение

Организаторы предложат критерий — **пилот** вносит его, **ведущий** проговаривает.

**Пилот:** «Чек-листы» → выбрать заменяемый критерий → название, «Когда „Да“», «Когда „Нет“», при необходимости тип и N/A → вес так, чтобы сумма осталась 100 → «Сохранить версию» → в диалоге выбрать CONTROL → «Оценить».

**Ведущий:**
> «Меняем критерий через интерфейс, без кода. Сумма весов проверяется до сохранения. Сохранение создаёт новую версию: старые оценки остаются со своей. Инструкция для модели и схема ответа собираются из сохранённой версии — новый критерий сразу попадает в оценку».

Очередь показывает прогресс. Пилот открывает первый готовый диалог или тот, что пишется в прямом эфире, — там новый критерий.

**Закрывающая фраза (10 секунд):**
> «Сверх задания — суфлёр, который подсказывает оператору прямо во время чата на быстрой модели Haiku, тренажёр с клиентом-симулятором и карта навыков операторов. С удовольствием покажем на вопросах».

## Если что-то пошло не так

| Что случилось | Что делать |
|---|---|
| Прямой эфир думает дольше 30 с | Не ждать: «модель ещё пишет, вот предыдущая оценка этого же диалога», выбрать её в списке истории в шапке карточки. |
| Ошибка API или нет сети | Переключиться на раздачу с телефона. Не помогло — запасное видео. Уже оценённое, апелляции и чек-листы работают без API. |
| Второе мнение долго не приходит | Выбрать ступень вручную, причину написать коротко — апелляция работает и без него. |
| Новый критерий не сохраняется | Внизу написано почему, чаще всего сумма весов ≠ 100. Поправить вес у соседнего критерия. |
| Отстаёте по времени | Пропустить «Как получена оценка», звонок и второе мнение — это не обязательная часть. |

## Ответы на вопросы

**Какая модель и сколько стоит?** Claude Opus 5.5 оценивает: три прогона одновременно, голосование, около $0,12 за чат и $0,19 за звонок; в режиме «1 прогон» — около $0,04. Суфлёр, тренажёр и план развития — Claude Haiku 5.5, около $0,002 за чат.

**Насколько точно?** На DEV 94% совпадений по критериям с нашей разметкой — это не официальный эталон. Отдельно проверяем на данных, которых не было при настройке: метаморфные тесты (убрали представление — «Установление контакта» должно упасть) — 18 из 18, контрастные диалоги — 16 из 16.

**Не подогнано ли под DEV?** В правилах только формулировки чек-листа и памятки, в промпте нет примеров из DEV. Точность проверяем на независимых наборах.

**Что если модель ошиблась?**
- Цитата проверяется кодом: она должна дословно быть в реплике.
- При ошибке модель получает одну попытку исправиться, иначе статус «Проверить».
- Расхождение прогонов видно у каждого критерия, есть фильтр «Модель сомневается».
- И апелляция.

**Как модель понимает «размытые» критерии — потребность, консультацию, ведение?** Модель называет факты: какие вопросы задал клиент, закрыт ли каждый, какие были сбои. Ступень по правилам чек-листа выводит код. Так ответы стабильнее.

**Почему не локальная модель?** Главный критерий — точность, поэтому взяли самую точную. Внешние вызовы изолированы в одном месте, модель можно заменить. Для подсказок в реальном времени уже используем дешёвую быструю модель.

**Звук анализируете?** Claude звук не принимает, поэтому запись разбирает код: темп речи, доля речи, интонация, громкость, паузы. Это справка проверяющему, в баллы не входит: эталон размечен по тексту. Чёткость дикции так не измерить, для неё нужна отдельная модель распознавания речи.

**Как встроить в Dynamics 365?** Интерфейс — статические HTML, CSS и JavaScript без сборки, адрес API задаётся одним атрибутом. Страницу можно загрузить как веб-ресурс, сервер оценки держать отдельно.

**Персональные данные?** Диалоги уходят в API Anthropic. В выданных данных имена и номера уже замаскированы. Для продакшена — корпоративный договор с API или замена модели через ту же точку подключения.

## Репетиция

Прогоните сценарий 2–3 раза с секундомером, каждый раз с отката базы. Цель — 4:30, полминуты держите на запас. Заранее заготовьте текст апелляции и пример нового критерия: например, «Предложил мобильное приложение», вес 15 вместо «Эмпатии».
