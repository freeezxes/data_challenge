# CQA на ortaresearch.com: отдельная версия с аккаунтами

Ветка `codex/ortaresearch-deploy`, рабочая папка `data_challenge-deploy`.
Основная версия и её `.env` не меняются. Веб-сервер не загружает `.env`
и не использует серверный `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN`.

## Аккаунты и сохранение

По актуальному запросу сайт открывается без обязательного входа (`CQA_GUEST_MODE=1`).
Гостевые импорты и результаты сохраняются в отдельной общей базе
`/srv/cqa/shared/guest/cqa.db`, доступной всем посетителям. Приватные базы аккаунтов
и их ключи гостям недоступны. Гостевой ключ хранится только в памяти вкладки до
перезагрузки и передаётся с запросами; на сервере не сохраняется. Личные настройки
гостя хранятся в браузере. Для приватного сохранения ключа и данных можно войти
через кнопку «Войти». Установка `CQA_GUEST_MODE=0` возвращает обязательный вход.

При первом запуске создаётся `admin` со случайным паролем. Реквизиты находятся
только на сервере: `/srv/cqa/shared/auth/admin-login.txt`, права 0600.
При повторном запуске пароль не меняется. Можно также создать свой аккаунт
на странице входа; пароль — от 12 символов, имя — 3–40 латинских букв,
цифр, точек, дефисов или подчёркиваний.

Существующая база `/srv/cqa/shared/cqa.db` принадлежит `admin`: ранее загруженные
импорты, оценки, версии чек-листа и апелляции остаются на месте. У каждого нового
аккаунта — отдельная база в `auth/workspaces/<внутренний-id>.db`. Идентификаторы
наборов, оценок, заданий, апелляций и токены предпросмотра действуют только внутри
своего аккаунта. Новый аккаунт получает исходный DEV и чек-лист организаторов.

Сохраняются импорты, оценки, чек-листы, апелляции и настройки интерфейса
(выбранный набор, роль, режим оценки, имя в тренажёре, название команды).
Повторный вход, другое устройство и перезапуск сервера не удаляют эти данные.
Несохранённые формы и незавершённые предпросмотры импорта остаются временными.

Кнопка «API-ключ» сохраняет пользовательский ключ Claude в зашифрованном виде
в базе аккаунтов. Полный ключ обратно в браузер не передаётся; API возвращает
наличие ключа и маску. Сохранение не вызывает модель. Ключ используется для
оценки, суфлёра и подсказок; удаление или замена влияет на новые запросы,
а уже запущенные задания заканчиваются со своим клиентом.

Пароли хешируются scrypt (N=32768, r=8, p=3, случайная соль); API-ключи
защищены Fernet с привязкой к внутреннему ID аккаунта. Мастер-ключ:
`auth/master.key`, права 0600. Его нужно сохранять вместе с резервной копией
базы аккаунтов; при потере сервер отказывается запускаться вместо генерации
нового ключа поверх существующей базы. Параметры scrypt соответствуют
[рекомендации OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html),
Fernet используется через [cryptography](https://cryptography.io/en/latest/fernet/).

Сессия хранится 30 дней в HttpOnly, Secure, SameSite=Lax cookie; на сервере
сохраняется только её хеш. Выход отзывает сессию. Изменяющие запросы защищены
CSRF-токеном, проверкой Origin и JSON-заголовками. На вход и регистрацию есть
ограничения частоты; вычисление хешей ограничено двумя параллельными запросами.
При выключенном гостевом режиме API продукта и файлы данных требуют входа.
`/api/health` не содержит пользовательских данных и показывает доступность гостевого режима.

## Проверка и обновление

```bash
.venv/bin/python -m pytest -q
bash deploy/package.sh /tmp/cqa-deploy.tar.gz
scp /tmp/cqa-deploy.tar.gz root@100.75.211.119:/tmp/
# На сервере: распаковать в новую папку, затем
CQA_RELEASE_ID=<commit> bash /path/to/release/deploy/install.sh
```

Архив включает только перечисленные исходники git: без `.env`, локальных баз,
мастер-ключей, реквизитов администратора, `.git`, `data/raw`, `data/runs`
и подписанных адресов организаторов. Релиз не заменяет `/srv/cqa/shared`.
Перед переключением сохраняется резервная копия текущих SQLite-баз через
SQLite backup API, мастер-ключа и nginx/unit-файлов в `shared/before-<commit>`.
Установщик запускает тесты, сервис и health check, затем проверяет nginx и HTTPS.

Перед обновлением дождитесь завершения активных оценок. Для первого запуска
без сертификата установщик отдаёт по HTTP только ACME и ответ обслуживания.
После привязки DNS получите сертификат существующим ACME-аккаунтом:

```bash
certbot certonly --non-interactive --webroot -w /var/www/cqa-acme \
  --cert-name ortaresearch.com -d ortaresearch.com -d www.ortaresearch.com \
  --deploy-hook 'systemctl reload nginx'
install -m 644 /srv/cqa/current/deploy/ortaresearch.conf /etc/nginx/sites-available/ortaresearch.conf
nginx -t && systemctl reload nginx
```

## Проверка после деплоя

```bash
systemctl status cqa.service
nginx -t
curl --fail https://ortaresearch.com/api/health
# Без cookie /api/state должен вернуть 401, / — перенаправить на /login.
```

После входа проверьте импорт, сохранение ключа, выход и повторный вход. Платную
оценку в автоматических проверках не запускаем; HTTP-тесты используют fake client.
Логи: `journalctl -u cqa.service`. Заголовки и тела запросов не логируются,
сообщения ошибок скрывают ключи. Debug-логирование HTTP SDK включать не следует.

CLI/harness остаётся отдельным инструментом. Он поставляется в релизе и при
платном запуске требует собственного ключа из окружения; ключ аккаунта сайта
автоматически в CLI не экспортируется. Не помещайте ключ в shell history:
`read -rs ANTHROPIC_API_KEY; export ANTHROPIC_API_KEY`, после прогона —
`unset ANTHROPIC_API_KEY`.

## Откат

Используйте предыдущий релиз с поддержкой аккаунтов и сохранённый unit/nginx
из `before-*`. Базы и master.key не заменяйте при обычном откате кода. После
появления приватных аккаунтов нельзя откатывать публичный сайт на версию без
авторизации: если совместимого релиза нет, оставьте ответ обслуживания до ремонта.
Восстановление данных требует согласованной копии SQLite-баз и master.key.
