# Журнал решений по разметке

Правила толкования каждого критерия лежат в `config/checklist.default.json` (поле `guidance`) — это единственный источник, его же видит модель. Здесь — почему приняты спорные решения и что уточнить у менторов.

## Почему 07 по умолчанию `lenient`
- В RU/EN голое прощание («Хорошего дня.», «Bye.», «Goodbye.») встречается почти только в заведомо плохих диалогах.
- В KZ есть безупречные чаты, где единственное отличие — голое «Сау болыңыз!» (`p1-kz-004`, `-007`, `-010`, `-014`): это похоже на тесты именно критерия 07.
- Пример из памятки для «Нет» — «закрыл чат без прощания», то есть ключевой признак — прощание.
- Тип завершения хранится в эталоне (`c07_closing`), политика переключается без переразметки.

## Другие решения
- 02 N/A, если оператор мог ответить сразу и ответил; «Нет» — переспросил известное или ответил наугад.
- 03 N/A, если оператор предложил идентификацию, клиент отказался и данные не раскрывались (`p1-ru-002`).
- 08 «Да» для раскрытия данных счёта без подтверждённой личности (`p1-ru-009`, `p1-kz-015`, `p1-en-014`) — помечено спорным.
- 04 для «средства D-счёта не используются напрямую» — 20 (ответ на вопрос дан).
- Звонки размечены с пометками спорности: ошибки распознавания речи не считаются ошибками оператора.

## Вопросы менторам (по приоритету)
1. «Пожалуйста. До свидания!» после «спасибо, нашёл» — это «Да» по 07? А голое «Сау болыңыз!»?
2. Раскрытие данных счёта без идентификации — это ещё и грубая ошибка (08) или только 03 = «Нет»?
3. Эталон по 10 контрольным диалогам — по каждому критерию или только итог?
4. Входят ли звонки в контрольный набор?
5. 03, если клиент отказался от идентификации и данные не раскрывались: N/A или «Да»?
