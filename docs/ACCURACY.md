# Точность оценщика

Эталон — рабочая разметка команды v4.1 (три независимых голоса по спорным местам), а не ответы организаторов.

## Рекомендуемая конфигурация

```bash
python scripts/run_eval.py --model claude-opus-5-5 --effort high --votes 3 --workers 4
```

Чек-лист `config/checklist.default.json` версии 8, без примеров в промпте. Около $0,13 за диалог при трёх голосах. При `--workers` больше 4 API начинает отвечать ошибкой лимита — недоделанное догоняется через `--resume`.

## Результаты (Opus 5.5)

| Проверка | v5, 1 голос | v7, 1 голос | v8, 3 голоса | v9 (ступени считает код), 1 голос | v10, 1 голос |
|---|---|---|---|---|---|
| DEV, средняя точность по критериям | 92,1% | 93,6% | 94,4% | 94,4% | **94,8%** |
| DEV, все 8 оценок совпали | 40/65 | 39/64 | **45/65** | 44/65 | 44/65 |
| DEV, отклонение итога (MAE) | 4,55 | 4,50 | **3,65** | 4,46 | 4,03 |
| Метаморфные тесты (не зависят от эталона) | 31/34 | 34/34 | 34/34 | **18/18** (3 исходника) | **18/18** |
| Контрастные диалоги вне DEV | — | 8/8 | 8/8 | **8/8** | **8/8** |
| Диалоги на выявление потребности вне DEV | — | 8/8 | 8/8 | **8/8** | **8/8** |

v8 по критериям на DEV: контакт, идентификация, грубые ошибки — 100%; эмпатия, завершение — 97%; выявление потребности — 92%; консультация — 89%; ведение диалога — 80%.

v9: для выявления потребности, консультации и ведения диалога модель отдаёт факты (какие вопросы задал клиент, закрыт ли каждый, какие были сбои), а ступень по правилам чек-листа выводит код (`cqa/derive.py`). Один голос v9 даёт ту же среднюю точность, что три голоса v8, то есть втрое дешевле. По сравнению с одним голосом v7: консультация 84% → 88%, ведение диалога 83% → 86%. Против трёх голосов v8: ведение диалога 80% → 86%; выявление потребности 92% → 91% и консультация 89% → 88% — разница в один диалог, в пределах разброса одного голоса. Метаморфные тесты стали стабильнее: на соседних критериях 1 сдвиг вместо 10. Оставшиеся промахи по выявлению потребности — спорные «переспросил известное» (p1-kz-003, p1-ru-017 — кандидаты на слепую переразметку). Стоимость прогона DEV — $2,8.

v10: две правки меток фактов по тексту чек-листа. (1) Вопрос о том, что клиент уже сообщил, — не сбой «Ведения диалога»: критерии независимы, повтор известного оценивает «Выявление потребности», а ведение — ясность, порядок ответов и предупреждение об ожидании. (2) Второстепенная деталь снижает «Консультацию», только если клиент сам о ней спросил. Итог: средняя точность 94,4% → 94,8%, отклонение итога 4,46 → 4,03, звонки 85% → 90%; консультация 88% → 89% (+1, новых промахов нет). Ведение диалога 86% → 83%, и это требует пояснения: правка (1) на DEV дала ноль — исправила p1-kz-003, p1-kz-012, p1-ru-017 и сломала p1-kz-008, p1-ru-014, p1-ru-026, потому что рабочая разметка команды противоречива: в одних диалогах повтор известного снижает ведение, в других нет. Ещё четыре новых промаха (p1-en-014, p1-kz-015, p1-ru-003, p1-ru-023) — разброс одного прогона (модель то отмечает «неясную формулировку», то нет); его сглаживают три прогона. Разметку не трогаем: менять эталон под ответы модели — та же подгонка. Правила v10 выбраны по разбору промахов DEV, поэтому их выигрыш на DEV (+0,4 п.п., в пределах разброса одного прогона) не считаем доказательством; на независимых наборах результат не изменился. Дальше DEV — только регрессионная проверка, новые правки по его промахам не делаем. Независимые проверки не изменились. Стоимость прогона DEV — $2,67, всей проверки — $4,25.

v11–v12 (без правок по DEV): (1) устойчивость к формулировкам системных сообщений — шаблоны эскалации, подтверждения личности и обрыва расширены на синонимы RU/KZ/EN, блок ФАКТЫ говорит «не распознано», а не «события нет», проверка доказательств принимает любое системное сообщение; метаморфная мутация «перефразировать системные сообщения» — ни один ответ не меняется (7/7). (2) Эмпатия и завершение выводятся кодом из фактов модели (выразил ли клиент недовольство, отреагировал ли оператор по сути, было ли прощание, итог или предложение помощи, оборвался ли чат) по тексту чек-листа; все факты критерия — одно строковое поле `facts`, иначе схема не проходит предел грамматики API. Новая мутация «клиент пожаловался, оператор отмахнулся» → эмпатия «Нет» (5/5). (3) Добор прогонов: если три прогона разошлись хотя бы по одному критерию, добираются ещё два. Полный метаморфный набор (8 мутаций × 3 исходника) при 3 прогонах с добором — 24/24, побочные сдвиги только на p1-kz-003 по выявлению потребности, где и исходный ответ спорный. Цена добора: средняя стоимость диалога $0,12 → $0,19, добор сработал в 10 из 27 диалогов. Замер: $6,05.

## Как избегали подгонки под DEV

- Подсказки в чек-листе — только общие правила из текста чек-листа и памятки; проверено, что в них нет фраз из DEV.
- Без примеров из DEV в промпте.
- Независимые проверки: метаморфные тесты (`scripts/run_metamorphic.py`, ожидание считается от ответа модели на исходный диалог) и наборы `data/calibration/*` с известными ответами.
- DEV-цифры — оценка сверху: правила v6–v8 правились по ошибкам на DEV. Ориентир для новых данных — независимые проверки.
